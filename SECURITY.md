# Security policy

## Supported code

Security fixes target the currently deployed production release and the active
release candidate. Older commits, local drafts, archived packages, and
third-party provider software are not separately supported.

## Report a vulnerability privately

Use the repository's **Security** tab and choose **Report a vulnerability**.
Do not open a public issue containing an exploit, personal data, provider
identifiers, authentication material, or details that would help reproduce an
attack before a fix is available.

If private vulnerability reporting is temporarily unavailable, a signed-in
MyPersonas owner can use **Report a problem** and begin the note with
`Security`. Send only enough detail to identify the affected route or feature.
Never submit passwords, session tokens, API keys, recovery codes, payment-card
data, raw private messages, or another person's personal information.

## Helpful evidence

- affected public URL or route, without secret query parameters;
- observed and expected behavior;
- browser and operating-system family;
- approximate UTC time;
- minimal redacted reproduction steps; and
- whether the issue appears to cross account, persona, or publication
  boundaries.

Do not access another person's data, disrupt service, run denial-of-service
tests, send automated traffic, contact users, or retain data while testing. A
report is not authorization to exceed your own account or ordinary public
access.

The operator will preserve the report as private security evidence, validate it
without expanding access, prioritize containment, and disclose a fix only when
doing so will not create additional risk. This policy does not promise a bounty,
response time, or permission to test third-party providers.
