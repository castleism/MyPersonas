Data Deletion Guide

Use these controls to export your data, disconnect providers, erase MyPersonas content, and request deletion of the remaining AliaSpaces sign-in record.

Effective July 28, 2026
Deleting MyPersonas data does not delete an external account. Your Gmail, X, Meta, OnlyFans, or other provider account and provider-hosted content remain under that provider’s control.

Before deleting

  1. Sign in to the correct AliaSpaces account. Open Matrix, then open Account & settings → Security.
  2. Download a copy if you want one. Select Download my data (JSON). The export excludes stored model keys and provider tokens.
  3. Pause automation. Use the global Matrix safety switch so no new draft, publishing, fan-chat, or mailbox work begins while you review deletion.
  4. Revoke providers where needed. Use the provider links below. Provider-side revocation is especially important when the app cannot prove the final token state.

Delete all MyPersonas content but keep sign-in

  1. Go to Security. In Matrix, open Account & settings → Security → Sessions & data.
  2. Select “Delete all my content.” Read the confirmation carefully. This action cannot be undone.
  3. Complete any provider-revocation prompt. If the page safely identifies OpenRouter, an uncertain X grant, or an unfinished Meta authorization for manual revocation, follow its provider link and confirm only after revocation is complete. One Meta authorization can cover every paired Facebook Page and linked professional Instagram account. If the page instead reports a Meta ownership investigation, do not revoke or acknowledge it from that sign-in; use Report a problem so the original owner connection is not disrupted.
  4. Wait for verified completion. The page enables deletion only when the server reports the content-only deletion contract. If the deletion service cannot be reached or cannot confirm success, the page does not claim deletion.

This removes owned personas, pages, posts, comments, reactions, albums, uploaded media, account inventory and connection records, drafts, schedules, content plans, linked models and encrypted credentials, automation and chat history, display name, preferences, and owner problem reports.

Your sign-in remains. Content erasure clears the private profile details but intentionally keeps the Supabase authentication record so you can still sign in.

Request deletion of the remaining sign-in record

The current public Security screen exposes verified content-only erasure, not a separate full-account button. To request full sign-in deletion:

  1. Run “Delete all my content” first. This removes the content and supported connected grants through the verified owner flow.
  2. While still signed in, press “Report a problem.” The button appears in the lower-left corner of the main MyPersonas / AliaSpaces application.
  3. Enter this exact request:Delete my remaining AliaSpaces sign-in record. Do not add a password, token, recovery code, or other credential.
  4. Keep provider revocations separate. Removing the sign-in record cannot remove copies held by Google, X, Meta, an AI provider, or another third party.

The signed-in report supplies the account identifier needed to locate the request without asking you to place authentication secrets in the note. No completion time is promised on this page.

Remove one saved or connected account

  1. Open Account & settings → Accounts. Expand the provider and select the saved account.
  2. Remove the account record. For Gmail and X, MyPersonas attempts to revoke supported access and remove its encrypted token before deleting the ledger record. Removing a connected Facebook Page or linked Instagram record revokes the complete shared Meta grant and disconnects every asset paired through it. A failed or uncertain revocation is shown instead of being silently treated as complete.
  3. Revoke at the provider too. Use its Connected Apps or security settings if you want to independently end access.

For inventory-only providers such as OnlyFans, removing the record deletes the MyPersonas identifier, assignment, notes, and planning link. It does not affect the external account because MyPersonas never had provider authorization.

Mailbox-specific effects

  • Disconnecting Gmail removes the stored MyPersonas grant and stops new scans and actions.
  • Deleting MyPersonas findings, plans, or audit records does not reverse changes already made in Gmail.
  • Use an available MyPersonas Undo before its displayed deadline if you need to restore labels or recover messages moved to Trash by an approved plan.
  • Gmail controls Trash retention. MyPersonas currently limits its displayed undo window to no more than 28 days and cannot restore mail after the provider removes it.
  • No MyPersonas deletion action deletes the Gmail account itself.

Browser data and public copies

After content erasure, MyPersonas clears account-scoped chat backups and selected preferences from the current browser. Because content-only erasure keeps sign-in, the Supabase session can remain. To remove remaining device data, sign out and clear site data for MyPersonas in your browser.

Public content or media may have been copied, embedded, indexed, downloaded, or cached by other people and services. MyPersonas deletion removes the owned source records and stored media it controls but cannot guarantee removal of independent third-party copies.

Never send credentials in a deletion request. MyPersonas does not need an external provider password, app password, recovery code, access token, API key, or session cookie to locate your signed-in request.

If the controls cannot be reached

Open the MyPersonas / AliaSpaces application and use Report a problem. Begin the note with “Data deletion,” describe the control you could not reach, and do not include credentials or payment information.

For more detail about the data involved, read the Privacy Notice.
